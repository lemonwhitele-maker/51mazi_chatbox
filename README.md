# 51mazi_chatbox

> 以书籍资料为基础、由作者决定内容取舍的 AI 小说创作工作台。

`51mazi_chatbox` 是基于 [51mazi](https://github.com/xiaoshengxianjun/51mazi) 官方 `v0.8.5` 继续开发的独立维护 Fork。它保留原项目的本地写作与创作工具，并将开发重点放在三件事上：**让 AI 围绕整本书持续协作、让建议有来源可检查、让正式修改始终由作者确认。**

> [!IMPORTANT]
> 当前仓库定位为**源码预览 / 早期开发版本**，适合愿意自行构建、备份作品并反馈问题的用户。它不是 51mazi 官方版本，也尚未同步上游后续版本的全部功能。

## 为什么做这个 Fork

长篇创作的问题通常不是“缺少一次生成”，而是正文、人物、设定、伏笔和讨论会不断增长。作者需要的不只是更多 AI 按钮，而是一个能够围绕作品持续工作的协作过程。

本分支遵循四项设计原则：

1. **一本书就是一个协作空间**
   正文、人物、设定、大纲、速记和历史讨论属于同一本书。切换模块时，不必反复复制整套背景。

2. **事实、计划与讨论彼此有别**
   已保存的正文是作品内容，大纲是计划，历史对话是讨论。AI 可以检索它们，但不会把一次头脑风暴自动当作正式设定。

3. **AI 提建议，作者做决定**
   AI 对正文和资料的改动先形成可审阅提案。只有作者确认、且目标版本仍然匹配时，内容才会写入文件。

4. **作品优先留在作者手中**
   书稿、知识文档、对话记录和提案保存在本地书库中。索引可以重建，作品不依赖某一次模型会话才能继续维护。

## 从问题到正式修改

```mermaid
flowchart LR
    A[提出问题或选中正文] --> B[按需检索书内资料与历史讨论]
    B --> C[给出带来源的建议]
    C --> D[生成修改提案]
    D --> E{作者审阅}
    E -->|接受| F[检查文件版本后写入]
    E -->|拒绝| G[不修改作品]
    F --> H[条件允许时安全撤销]
```

这条流程的重点不是让 AI 自动接管写作，而是减少整理资料和落实修改时的机械工作，同时保留作者对作品的最终控制。

## 本分支的主要更新

### 1. 书籍工作区与常驻 AI 对话

- 将正文、人物、设定、大纲、速记等模块放在同一书籍工作区中。
- 提供可收起、可调整宽度的对话侧栏，切换功能时可以继续当前任务。
- 支持为人物塑造、情节规划、资料整理等任务建立多个对话。
- 对话、摘要、工具记录和修改提案由应用保存，不把长期创作过程只托付给模型会话。

### 2. 书籍资料与历史讨论检索

- 浏览书籍结构并搜索正文、人物、设定、大纲、速记和历史对话。
- 按需读取与当前问题相关的局部内容，减少无关上下文。
- 在回答中保留来源信息，方便作者回到原文核对。
- 支持人物、设定、大纲之间的引用，以及大纲与章节的关联。

### 3. 可审阅的修改提案

- 正文支持选区替换、选区前后插入和章末追加。
- 人物、设定、大纲和速记支持资料修改提案。
- 提案写入前会检查文件版本，避免旧建议覆盖作者之后的手动修改。
- 已应用的修改在满足版本条件时可以安全撤销。
- 未确认或已拒绝的建议不会进入正式作品。

### 4. 开放式 Markdown 知识文档

- 人物、设定和大纲统一使用独立 Markdown 文档。
- 在必要的标识、元数据和引用约定之外，允许作品保留自己的字段和内容结构。
- 大纲可通过标签、顺序、关联大纲和章节引用组织，不强制所有作品使用同一种固定层级。
- 文档索引提供诊断与重建能力；源文档仍是可直接备份和读取的本地文件。

### 5. 人物图与关系图联动

- 在新版人物页面生成 `720 × 1280` 竖版人物图并预览候选结果。
- “使用图片并保存人物”会同时保存当前人物文字和选中的头像。
- 已确认图片保存在所属书籍的 `character_images` 中，文档记录书内相对路径，便于移动整套书库。
- 人物列表显示缩略图；关系图中已关联人物可同步头像，手动设置的节点图片保持独立。
- 发生版本冲突或保存失败时保留编辑内容和候选图片，便于处理后重试。

### 6. 可随书库搬迁的应用级 API 配置

- 聊天模型、功能 API、DeepSeek、通义万相、Gemini、豆包及图片服务商选择统一保存在 `BookList/.51mazi/api-config.json`。
- 配置仍由整个应用共享，不需要为每一本书重复填写。
- 切换到已有配置的书库时读取其配置；目标书库没有配置时，可带入当前共享配置。
- 迁移采用备份、原子写入和读取校验，成功后才清理旧应用配置中的对应 API 项。
- 书库根目录的 `.51mazi` 不会被识别成一本书，也不会进入正文导出或书籍检索。

### 7. 为不同模型接入方式保留空间

- 支持 Codex App Server 路径。
- 支持由用户显式配置的 OpenAI 兼容 API 路径。
- 对话标题等轻量任务可以使用独立的功能 API 配置。
- 不在失败时静默切换到另一个服务，尽量让实际使用的后端保持可见。

> 配置界面中出现某个厂商或模型名称，不等于该组合已经完成兼容性认证。请以实际测试结果为准。

## 与上游 `v0.8.5` 的侧重点差异

| 方向 | 上游基础 | 本分支的重点 |
| --- | --- | --- |
| AI 交互 | 润色、续写、按大纲生成等功能入口 | 围绕一本书持续对话，并由应用保存协作过程 |
| 上下文 | 为特定任务聚合书籍资料 | 按需搜索、局部读取、来源引用和历史讨论检索 |
| 内容写入 | 各功能分别确认生成结果 | 正文和知识资料使用统一的提案、版本检查与撤销流程 |
| 人物 / 设定 / 大纲 | 固定表单或专用数据结构 | 可扩展的 Markdown 文档与跨资料引用 |
| 人物图片 | 旧人物资料和图片流程 | 接入新版人物文档，以相对路径随书保存并同步关系图 |
| API 配置 | 应用配置与书库分离 | 应用级配置随完整 `BookList` 一起搬迁 |

本分支已经移除旧人物完整档案与人物图库、紧凑树形大纲、旧大纲 AI 草稿工作台及其专用代码，统一转向新版 Markdown 工作区。**旧格式人物、设定和大纲不会自动迁移**；首次打开旧作品时，请务必使用副本验证。

## 继承的创作能力

除上述改造外，本项目继续保留 51mazi 的主要本地创作基础，包括：

- 多书籍管理与章节编辑；
- 本地封面和 AI 封面；
- 地图设计、关系图谱、时间线、事序图和组织架构；
- 词条字典、随机名字和笔记；
- 小说正文导出；
- 书架与单本书密码等原有能力。

具体可用功能以当前源码和实际界面为准。

## 数据保存、搬迁与隐私

典型的数据结构如下：

```text
BookList/
├─ .51mazi/
│  └─ api-config.json          # 整个书库共享的 API 配置
└─ 作品名/
   ├─ mazi.json
   ├─ 正文/
   ├─ knowledge/
   │  ├─ characters/
   │  ├─ settings/
   │  └─ outlines/
   ├─ character_images/
   └─ .51mazi/                 # 对话、提案、速记及相关应用数据
```

在自己的设备之间搬迁时，请复制**完整 `BookList`，包括隐藏的 `.51mazi` 目录**，然后在新设备中重新选择该书库。这样可以一并带走书籍、已保存人物图片、对话协作数据和软件内 API 配置。

同时请注意：

- `api-config.json` 包含你填写的访问凭据，应被视为敏感文件；不要上传到 GitHub，也不要随公开书稿分享。
- 小说正文导出不包含 API 配置；直接分享完整书库时仍需主动排除 `.51mazi` 中的配置与迁移备份。
- 外部 Codex 的安装、登录和自身配置不在这套迁移范围内，需要单独处理。
- 尚未保存的编辑草稿不属于书库搬迁保证范围。
- 书籍资料默认保存在本地；使用远程 AI 时，完成当前请求所需的选区、资料片段和对话上下文会发送给你选择的服务。请同时阅读相应服务商的隐私政策。

### 关于公开源码中的数据

最近一次源码检查未发现真实 API key、私人书库、章节数据库或备份。仓库仍包含用于演示功能的虚构人物 / 设定 / 大纲，以及离线测试使用的合成文本；这些内容不是用户作品数据。

## 从源码运行

### 环境要求

- Node.js 20（与当前自动构建环境一致）
- npm
- Windows、macOS 或 Linux 开发环境

### 安装与启动

```bash
npm ci
npm run dev
```

首次启动后：

1. 选择或创建一个本地书库目录，例如 `BookList`。
2. 新建一本测试书，先熟悉资料结构和提案确认流程。
3. 如需 AI 功能，在设置中填写你自己的模型或图片服务配置。
4. 使用旧作品前先复制备份，不要直接用唯一原件测试早期版本。

### 构建

```bash
npm run build

# 按平台生成安装包
npm run build:win
npm run build:mac
npm run build:linux
```

### 发布前校验

```bash
npm run verify:release
```

该命令依次执行静态检查、离线回归测试和生产构建。涉及真实模型、系统权限、安装包升级和跨平台表现的部分仍需单独验收。

## 当前限制

- 当前是早期源码预览，不承诺生产环境稳定性。
- 知识文档目前仍偏向 Markdown 源码编辑，低门槛表单和所见即所得体验有待完善。
- 不提供旧人物、旧分类设定、旧树形大纲和旧大纲草稿的自动迁移。
- 不同 API 服务对工具调用和兼容格式的支持不一致，尚未对配置列表中的所有组合逐一认证。
- 基于 `v0.8.5` 开发，不自动包含上游后续版本新增的全部功能。
- 在迁移旧作品或尝试 AI 写入前，应保留可独立恢复的书库备份。
